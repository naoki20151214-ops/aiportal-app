# AI Portal Master Content Registry

このディレクトリは、AI Portal のコンテンツ設計における **Single Source of Truth** です。

記事数そのものを目標にせず、「AIを体系的に学ぶために必要な知識ノード」を定義し、記事・内部リンク・学習順序・公開状態を一貫して管理します。

## ファイル

- `taxonomy.yml` — カテゴリ、LEVEL、記事タイプ、公開状態などの固定語彙
- `knowledge-nodes.yml` — 記事候補を含む全知識ノードと知識グラフ
- `learning-paths.yml` — 初心者から専門領域へ進む推奨学習経路
- `publishing-plan.yml` — 公開順・公開速度・スケジュール運用ルール

## 基本原則

1. 記事数をKPIにしない。必要な知識ノードを作る。
2. 1記事につき1つのCenter Questionを持つ。
3. カテゴリは `taxonomy.yml` の7カテゴリだけを使う。
4. 会社名・製品名・画像/動画などの細分類は原則タグで扱う。
5. LEVEL 0〜5で読者の前提知識を明示する。
6. `prerequisites` は「先に読むと理解しやすい記事」。
7. `children` は「この概念から直接深掘りする記事」。
8. `related` は横断的に関連する記事。
9. 未公開ノードはURLリンクとして公開しない。UIでは必要に応じて「準備中」と表示できる。
10. `published` のノードは必ず実記事と1対1で対応させる。
11. ニュースは単発で終わらせず、既存のエバーグリーン知識へ接続する。
12. 一次情報を優先し、重要な事実は公開前に検証する。
13. 長さに固定上限を置かない。「その問いを理解できる」ことを完成条件とする。
14. 知識グラフを壊す変更はCIで検出する。

## LEVEL

- LEVEL 0: 完全初心者 — 用語を知らなくても読める
- LEVEL 1: 基礎 — 基本用語を理解する
- LEVEL 2: 仕組み — 内部構造・原理を理解する
- LEVEL 3: 実践 — 実際に使う・作る
- LEVEL 4: 専門 — 設計・運用・最適化
- LEVEL 5: 研究・設計 — 高度な研究・アーキテクチャ・評価

## Status

`planned → draft → review → ready → scheduled → published`

- `planned`: 設計済み、未執筆
- `draft`: 執筆中
- `review`: 技術・編集レビュー中
- `ready`: 公開可能
- `scheduled`: 公開日時決定済み
- `published`: 公開済み

## 運用

新しい記事を作る前に `knowledge-nodes.yml` にノードを追加します。
既存ノードで扱えるテーマを重複作成しないでください。

公開済み記事を追加・削除・slug変更する場合は、Registryも同じPRで更新します。

このRegistryはChatGPT、Codex、人間編集者のいずれが作業しても同じ設計を引き継げることを目的とします。

## 現在のベースライン

Registry v2では、エバーグリーン知識を中心に500ノードまで拡張しています。

- AI基礎・技術: 100
- 生成AI: 105
- AIエージェント: 80
- フィジカルAI・ロボティクス: 60
- AI開発・インフラ: 75
- AI活用・社会: 78
- AIニュース: 2

500は上限ではありません。知識の網羅性を優先し、必要に応じて1000・2000ノード以上へ拡張します。
