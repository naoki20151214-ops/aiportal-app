現代のAIというと、ChatGPTのような大規模言語モデルや、画像認識に使われるニューラルネットワークを思い浮かべる人が多いでしょう。

しかしAI研究では長い間、別の考え方が中心でした。

それが、**世界についての知識を「記号」として表し、論理やルールを使って推論する**シンボリックAI（Symbolic AI）です。

たとえば、

- 「犬は哺乳類である」
- 「哺乳類は動物である」
- 「犬はポチである」

といった知識をコンピューターが扱える形で明示し、その関係から新しい結論を導きます。

この記事では、シンボリックAIとは何かを、**知識表現 → 推論 → 探索 → 機械学習との違い → 現代AIでの使われ方**という順番で整理します。

前提として、[AIとは何か？](/articles/what-is-ai)と[AIの歴史](/articles/ai-history)を読んでおくと位置づけが分かりやすくなります。

## 最初に結論：シンボリックAIは「知識を明示し、その知識を使って考えるAI」

シンボリックAIの中心にある発想は非常にシンプルです。

**人間が理解できる知識を、コンピューターが操作できる記号へ変換する。**

そして、

1. 事実を持つ
2. ルールを持つ
3. 条件を照合する
4. 新しい結論を導く

という処理を行います。

たとえば、

- 犬は哺乳類
- 哺乳類は動物

という2つの知識があれば、

- 犬は動物

という結論を導けます。

ここで重要なのは、答えだけでなく、**どの知識とルールを使って結論に到達したかを追いやすい**点です。

シンボリックAIでは、知識が大量の数値パラメータに分散して隠れるのではなく、比較的人間が読める形で表現されます。

Stanford HAIの解説では、初期から発展したTraditional AIの特徴として、明示的にプログラムされたルール、論理、人間が定義した知識を利用する方式が説明されています。

## 「Symbol＝記号」とは何を意味するのか

ここでいう「記号」は、単なる文字やアイコンという意味ではありません。

**現実世界の対象・概念・関係を、コンピューターが扱える表現へ対応させたもの**です。

たとえば、

- PERSON(Taro)
- DOCTOR(Taro)
- HAS_SYMPTOM(PatientA, Fever)

のような表現を考えられます。

意味としては、

- 太郎は人である
- 太郎は医師である
- 患者Aには発熱がある

という知識です。

人間にとっては普通の文章ですが、AIシステムではこれをより形式的な表現へ変換することで、検索したり、ルールへ当てはめたり、推論したりできます。

つまりシンボリックAIでは、まず**「世界をどのような記号で表すか」**が重要になります。

## Knowledge Representation：知識をどう表すのか

シンボリックAIでは、知識を持っているだけでは不十分です。

コンピューターが扱える構造で表現しなければなりません。

この分野を**Knowledge Representation（知識表現）**と呼びます。

代表的な方法を見てみましょう。

### 1. ルール

最も直感的なのがIF-THEN型のルールです。

たとえば、

**IF 発熱 = あり  
AND 咳 = あり  
THEN 呼吸器感染症を疑う**

のように書きます。

条件が成立すると、結論や次の処理を実行します。

業務ルール、診断、制御などで理解しやすい形です。

### 2. 論理

命題論理や述語論理などを使って、事実や関係を形式的に表します。

たとえば、

- すべての人間は死ぬ
- ソクラテスは人間である

という知識から、

- ソクラテスは死ぬ

という結論を導くような考え方です。

論理を使うと、「どの前提から何が導けるか」を厳密に扱えます。

### 3. 意味ネットワーク

概念同士をノードと関係でつなぎます。

たとえば、

犬  
→ 種類  
→ 哺乳類  
→ 種類  
→ 動物

のように、概念間の関係をネットワークとして表現します。

現代のKnowledge Graphにもつながる考え方です。

### 4. Frame

ある対象について、属性をひとまとめにして表します。

たとえば「車」というFrameなら、

- タイヤ数
- 色
- メーカー
- 車種
- 所有者

などの属性をまとめられます。

「対象についての知識を構造化して持つ」方法です。

### 5. Ontology

ある分野で、

- どんな概念が存在するか
- それらがどのような関係にあるか
- どの分類に属するか

を体系的に定義します。

医療、製造、企業データなど、大規模な知識管理で重要な考え方です。

## Inference：持っている知識から新しい結論を導く

知識を保存しただけではAIは判断できません。

次に必要になるのが**Inference（推論）**です。

推論とは、

> すでに知っている事実やルールを使って、新しい事実や結論を導く処理

です。

単純な例を考えます。

事実：

- Machine-Aの温度は95℃
- Machine-Aの安全上限は80℃

ルール：

- IF 温度 > 安全上限  
  THEN 過熱アラーム

するとシステムは、

- Machine-Aは過熱状態

という結論を導けます。

シンボリックAIでは、**判断根拠がルールとして見える**ため、「なぜこのアラームが出たのか」を追跡しやすくなります。

## Forward Chaining：分かっている事実から先へ進む

推論方法の代表例がForward Chaining（前向き推論）です。

現在分かっている事実から、使えるルールを順番に適用します。

たとえば、

1. 温度 = 95℃
2. 80℃を超えている
3. 過熱ルールが成立
4. 過熱アラーム
5. 装置停止ルールが成立
6. 安全停止

という流れです。

**「今分かっていることから、次に何が言えるか？」**

を前向きに進めます。

監視システムやイベント処理と相性がよい考え方です。

## Backward Chaining：確認したい結論から逆にたどる

Backward Chaining（後ろ向き推論）は逆方向です。

まず、

> Machine-Aは過熱しているのか？

という確認したい結論を置きます。

そして、その結論を成立させるには何が必要かを逆向きに確認します。

- 過熱している？
- その条件は？
- 温度が上限を超えている必要がある
- 実際の温度はいくつか？

という流れです。

診断や問い合わせ型のシステムでは、この方法が使いやすいことがあります。

## Search：AIは候補の中から答えを探す

シンボリックAIは「IF-THENだけのAI」ではありません。

もう一つ重要なのが**Search（探索）**です。

たとえばチェスでは、現在の盤面から可能な次の手が複数あります。

それぞれの手から、

- 相手はどう動くか
- その次はどうするか
- どの状態が有利か

と候補が枝分かれします。

AIはこのような**状態空間**を探索し、目的に近い経路を探します。

経路探索、ゲーム、スケジューリング、計画問題などで、探索はAIの基本技術として長く研究されてきました。

したがって、シンボリックAIを理解するときは、

- 知識表現
- 論理推論
- 探索
- 計画

という複数の要素を含む大きな系統として見る必要があります。

## 具体例：工場設備の初動判断

製造現場を例にすると分かりやすいでしょう。

ある装置で、

- 真空圧力が規定値に届かない
- ポンプは運転中
- バルブ開信号あり

という状態があったとします。

ルールとして、

- IF ポンプ停止 → ポンプ系を確認
- IF ポンプ運転中 AND バルブ閉 → バルブ系を確認
- IF ポンプ運転中 AND バルブ開 AND 圧力異常 → リーク・配管・シールを確認

と記述しておけば、確認すべき系統を絞り込めます。

これは「装置が自分で人間のように経験を学んだ」というより、

**熟練者の切り分け手順を知識として表現し、一定の順序で推論している**

と考える方が近いでしょう。

この考え方はエキスパートシステムへ直接つながります。

## シンボリックAIとエキスパートシステムの違い

この2つは同じ意味ではありません。

**シンボリックAI**は、記号・論理・知識・探索などを使うAIの大きなアプローチです。

**エキスパートシステム**は、その考え方を使って、特定分野の専門家の判断を再現しようとした代表的なシステムです。

関係としては、

シンボリックAI  
└ エキスパートシステム

と考えると分かりやすいでしょう。

エキスパートシステムでは、

- Knowledge Base
- Rule
- Inference Engine
- Explanation

などを組み合わせて、専門家のような助言や診断を行います。

## 機械学習との最大の違いは「知識がどこから来るか」

シンボリックAIと機械学習の違いを一言で言うなら、

**判断に使う知識を、誰がどのように作るか**

です。

### シンボリックAI

人間が知識・概念・関係・ルールを明示します。

例：

- IF 温度 > 80℃ THEN 異常
- IF 顧客年齢 < 18 THEN 契約不可

ルールを人間が読めます。

### 機械学習

大量のデータを使ってモデルのパラメータを調整し、データの中にあるパターンを学習します。

たとえば画像分類モデルなら、

「猫には耳が2つある」
「この形なら猫」

というルールを一つずつ人間が記述するわけではありません。

多数の画像から、分類に役立つ特徴がモデル内部へ分散して学習されます。

## どちらが優れているのか

単純に勝ち負けで考えるべきではありません。

得意な問題が違います。

### シンボリックAIが得意

- 規則が明確
- 判断理由を説明したい
- 厳密な条件を守らせたい
- 専門知識を明示的に管理したい
- 学習データが少ない

### 機械学習が得意

- ルールを手で書き切れない
- 画像・音声・自然言語など曖昧な入力
- 大量データから複雑なパターンを見つけたい
- 判断境界が人間には明示しにくい

実際の製品では、両方を組み合わせることが珍しくありません。

## シンボリックAIの強み

### 1. 知識を明示できる

「このシステムは何を知っているのか」を確認できます。

知識ベースやルールを人間が読めるため、監査や修正もしやすい場合があります。

### 2. 判断理由を追いやすい

どの事実とルールが使われたか記録すれば、

> なぜこの結論になったのか

を説明できます。

これは医療、業務ルール、安全制御などで重要です。

### 3. 厳密なルールを守らせやすい

「絶対にこの条件では実行しない」といった制約を明示できます。

確率的なモデルへ任せたくない処理に向いています。

### 4. 必ずしも大量データを必要としない

ルールが既知なら、何百万件もの学習データを集めなくてもシステムを作れます。

## シンボリックAIの弱み

### 1. Knowledge Acquisitionが大変

現実世界の知識をすべて人間が書くのは大変です。

専門家が持つ知識の中には、

- 経験で判断している
- 微妙な違和感で分かる
- 言葉にするのが難しい

という暗黙知もあります。

これをすべてルールへ変換するのは簡単ではありません。

### 2. 例外が増えるとルールが複雑になる

最初は10個のルールでも、

- 例外
- 例外の例外
- 新しい制度
- 新しい設備
- 特殊ケース

が増えると管理が難しくなります。

ルール同士が矛盾することもあります。

### 3. 画像・音声など曖昧な入力が苦手

「猫の画像」をすべてルールだけで説明するのは現実的ではありません。

色、形、姿勢、背景、光などが無数に変化するからです。

こうしたパターン認識では機械学習が大きな力を発揮しました。

### 4. 常識を全部書くのが難しい

人間は、日常世界について膨大な常識を持っています。

たとえば、

- コップを落とせば下へ落ちる
- 雨の中に長くいれば濡れる
- 閉じた箱の中身は外から見えない

といった知識です。

これらを一つずつ形式化してAIへ与えることは非常に困難です。

John McCarthyらが取り組んだ「常識知識を形式化する」研究は、シンボリックAIの重要性と難しさの両方を示しています。

## Symbol Groundingという難問

もう一段深く考えると、

> 記号が現実世界の何を意味しているのか、AIはどう結びつけるのか

という問題があります。

たとえばコンピューター内部に「APPLE」という記号があっても、それだけでは、

- 果物としてのリンゴ
- 企業名のApple
- 赤い物体
- 食べられるもの

という現実世界の意味は自動的には決まりません。

**記号と現実の意味をどう結びつけるか**は、AIにとって根本的な問題の一つです。

初心者段階では、まず「記号を作れば終わりではなく、その記号を現実世界の意味へ対応させる必要がある」と理解しておけば十分です。

## ニューラルネットワークはシンボリックAIの反対なのか

完全な反対ではありません。

両者は主に**知識の持ち方が違う**と考えると理解しやすいでしょう。

### シンボリックAI

知識：

> IF A AND B THEN C

のように明示的。

### ニューラルネットワーク

知識：

大量のWeightや内部表現へ分散。

人間が一つのルールとして直接読むことは難しい。

シンボリックAIは「人間が読める知識」に強く、ニューラルネットワークは「データから複雑なパターンを学ぶこと」に強い。

それぞれに利点があります。

## 現代AIでは「組み合わせる」という考え方が重要

現代のAIサービスでも、ニューラルネットワークだけですべてを処理しているとは限りません。

たとえば、

1. LLMがユーザーの文章を理解する
2. プログラムが入力形式を検証する
3. データベースから正確な情報を取得する
4. ルールエンジンが権限条件を確認する
5. LLMが結果を分かりやすく説明する

という構成が考えられます。

ここでは、

- ニューラルAI
- データベース
- ルール
- プログラム
- 外部ツール

を組み合わせています。

つまり実務では、

> すべてをAIモデルに任せる

よりも、

> **得意な部分をそれぞれの技術へ任せる**

設計が重要です。

## Neuro-Symbolic AIとは

ニューラルネットワークとシンボリックな推論を組み合わせようとする研究は、一般に**Neuro-Symbolic AI**と呼ばれます。

狙いは、

- ニューラルネットワークの認識能力
- シンボリックAIの明示的な知識・推論

を組み合わせることです。

たとえば、

画像をニューラルネットワークで認識  
↓  
認識結果を記号へ変換  
↓  
ルールや論理で推論

という構成が考えられます。

すべての問題がこの形で解決できるわけではありませんが、「学習かルールか」の二者択一ではないことを理解するうえで重要です。

## 現代でも使われるシンボリックな考え方

シンボリックAIという名称を使わなくても、その考え方は多くの場所に残っています。

### 業務ルール

- 利用資格
- 承認条件
- 料金条件
- 安全条件

など。

### Knowledge Graph

企業、商品、人、場所などの関係を明示的に表します。

### Ontology

専門分野の概念体系を共通化します。

### Planning

目的達成までの行動系列を探索します。

### Constraint

「これはしてはいけない」という制約を明示します。

### AIエージェント

LLMが計画・判断を行いつつ、ルール・権限・ツール仕様によって行動範囲を制御する設計があります。

こうして見ると、シンボリックAIは「過去のAI」ではなく、**現在のAIシステムを理解するためにも必要な考え方**だと分かります。

## よくある誤解

### 「シンボリックAIは古いから不要」

違います。

中心技術の流行は変わりましたが、ルール、論理、知識表現、探索、制約という考え方は現在も使われています。

### 「機械学習ならルールは一切不要」

これも違います。

実際のAI製品では、モデルの外側に多数のルールが存在します。

セキュリティ、アクセス制御、安全条件、入力検証などはその代表例です。

### 「説明できるAIなら正しい」

説明可能性と正しさは別です。

ルールが間違っていれば、AIは間違った推論を非常に論理的に実行できます。

### 「ルールを書けば必ず安全」

ルールに書かれていない状況や、複数ルールの矛盾もあります。

明示的であることは大きな利点ですが、設計・検証・保守は必要です。

## シンボリックAIを一言で説明するなら

シンボリックAIとは、

> **人間が理解できる形で知識を表し、その知識を論理・ルール・探索によって操作して答えを導くAI**

です。

現代の生成AIとは見た目が大きく違います。

しかし、

- AIにどんな知識を持たせるか
- どう推論させるか
- なぜその答えになったのか
- どの制約を必ず守らせるか

という問いは、現在のAIでも重要です。

## まとめ

シンボリックAIは、**知識を記号・事実・関係・ルールとして明示し、それらを操作して推論するAIのアプローチ**です。

AI研究の初期から大きな役割を果たし、エキスパートシステム、知識表現、探索、計画などの研究へ発展しました。

強みは、

- 知識が見える
- 判断理由を追いやすい
- 厳密なルールを扱いやすい

こと。

弱みは、

- 知識を人間が記述する負担
- 例外や常識をすべて表現する難しさ
- 画像や音声のような曖昧な入力への弱さ

です。

そして現代では、シンボリックAIと機械学習を完全に分離するのではなく、**それぞれの強みを組み合わせる**ことが重要になっています。
