# AI Portal｜ニュースの完全自動化・段階的な実装仕様

## 2026-10-19：無料の一次資料証拠パケット（ステージ1.5）

- 毎時の一次ページ取得結果 `artifacts/news-primary-evidence.json` と、自動調査候補 `artifacts/news-autonomous-research-shadow.json` を候補ID・公式URL・発表日時・発信元IDで照合する。
- `scripts/news-free-source-dossiers.mjs` が、一次資料URL、原文の見出し、日付、**最大320文字の短い導入文抜粋**、資料スナップショットSHA256を `artifacts/news-free-source-dossiers.json` に保存する。元記事のHTML全文は保存しない。
- 日付が一致しない／公式ドメイン外へリダイレクト／本文抜粋不足／403／重複した資料ID／研究候補との不一致は公開禁止・機械取材保留にする。過去に却下した同一ニュースは前段の研究選別で保留。
- **この抜粋は引用元が供給したメタデータであって、正しい主張や言語モデルによるファクトチェックの証明ではない。** `verifiedClaimIds: []`、`claimsVerified: false`、`aiDraftEligible: false`、`publicationEligible: false` と固定する。引用文に紛れた指示に従わない。
- 追加API費用0円、AI API呼び出し0回、ユーザー承認の偽装なし。収集ジョブはGitHub Actions `contents: read` で、非公開の14日アーティファクトのみ保存する。既存記事と即時公開ワークフローは変更しない。
- **次の依存工程**：本当に事実を確認できる一次原文の短い根拠抽出／新旧差分／数値・提供条件照合と、その引用文が各主張を支持するかの独立校閲。これを実装・実測しない限り、自律執筆・自律公開はONにしない。

## 現在の到達点（ステージ1：shadow）

毎時07〜23時JSTの10媒体公式RSS → 厳格な一次ページ取得補助 → 非公開トリアージ → **`scripts/news-autonomous-shadow.mjs`が研究すべき候補を決定論的に抽出** → GitHub Actionsのprivate artifactへ保管。

出力：`artifacts/news-autonomous-research-shadow.json`。`sourceId`、`originalUrl`、`candidateId`、発表日時、研究優先度、保留理由、証拠がまだ確定していないことを記録。GitHub main・Registry・記事・公開承認キューには書かない。これはニュースの「重要度」や「事実の正確性」をAIが証明したという意味ではない。**今は記事の自動生成・自動公開のいずれも無効**。

`content/news/autonomous-editorial-policy.json`で明示的に`mode: "shadow"`、`automaticDraftingEnabled: false`、`automaticPublicationEnabled: false`を固定し、違う値はCLIが停止する。候補を同時に6件まで調査順へ載せるのは**研究計算量の上限**であって、ニュースの投稿本数制限ではない。残りの候補は未処理理由付きで保持する。

## 2026-10-19｜無料で進める公式資料の根拠アンカー（追補）

自動取材への前工程として `scripts/news-official-evidence-anchors.mjs` を追加する。これまでの短いタイトル・日付・リードに加え、既存の384KB・12秒上限で安全に取得済みの**公式HTMLの同じレスポンス**から、`<article>` または `<main>` 内にある最初の意味のある段落を最大3箇所、各170文字まで取り出す。全段落や原文記事は保存しない。引用箇所と元段落のSHA-256をprivate artifactに記録し、再取得や内容の変化を調べる際の手がかりにする。

- 元資料を取得できない（HTTP 403、HTMLサイズ超過）、本文の意味領域が存在しない、まとまった段落がないときは「引用不可」として保留。**別媒体の推測やLLMで穴埋めしない**。全記事の自動公開を許可するものではない。
- `checkLiteralCitationAnchors` は短い引用が**取得した該当段落の文字列と完全に一致するか**だけ検証する。数値・日付や因果関係の**意味的な正しさを判定したものではない**ので、結果は必ず `semanticClaimsVerified: false`、`publicationEligible: false`。
- 収集した外部HTML・引用文は信頼しないデータ。そこにある「指示」を実行せず、ロゴ・広告・埋め込みscript・navigation/footerなどは避ける。
- Cloudflare Freeプランの実契約はまだ未検証。**追加有料AI APIを呼び出さない**。ニュース本番公開、オーナー承認、編集台帳、候補の順位付けには影響しない。
- ここから自律原稿生成を行うには、公式本文をもとに各主張への出典対応・意味的な独立評価・権利確認・コスト制限を別途実装し、実データで品質測定してから有効化する。

## ステージ2：一次資料の自律取材とAI原稿生成（今後実装）

- 一次ページのHTML全文は収集していない。現在はタイトル・日付・短い導入文だけであるため、事実を確認できない限り、いかなるAPIモデルにも「検証済みの主張」として渡してはならない。403・巨大HTML・日付不明は保留し、利用規約を破る回避策は使わない。
- 発行元が許す形式で、公式本文から短い根拠スパンと日付・対象・制限・数値のコンテキストを切り出す。安全なHTTPS/公式ホスト制限、容量、時間、robots/利用条件、外部文書内のプロンプトインジェクションを扱う。
- 研究候補をAIが採点する場合も、読者への重要性・実測の新規性・過去記事との差・実用上の影響を**別々の理由と根拠URL**で記録。誇張や未確認のベンチマークを禁止。
- 文章構成：**重要度/対象読者 → 結論 → 従来との違い → 具体例 → 限界と未確認事項**。一記事1分目安、ニュースの事実は claim-to-source IDs に紐付ける。既存の`scripts/news-model-draft-core.mjs`は人手確認済みパケット専用で、直接使って人手レビュー済みと偽装しない。機械取材専用の入力・出力スキーマを新設する。
- APIへの接続は権限分離したGitHub Actionsシークレットが必要。**現時点では`OPENAI_API_KEY`やモデル設定が本番環境にあるか未検証**。キーをログ・リポジトリ・公開ファイルへ書かない。コスト上限、429/5xx/タイムアウト対策、プロバイダー障害時の停止を設ける。
- オリジナル画像は適法な素材とAI Portal自身の生成物に限定し、WebP形式・寸法・サイズ・SHAを検証する。発行元のロゴ・図表は許諾なしに複製しない。

## ステージ3：独立校閲・自律的な公開承認（評価完了後のみ）

- 「AIが書いた」事実と「裏付けがある」事実を分離。執筆モデル自身の自己採点ではなく、独立した校閲工程で claim-to-source の**各主張が元資料から論理的に支持されているか**、量的数値・単位・日付・対象・提供地域・設計値と実績が混同されないかを検証する。
- 用途上重大な主張（安全、サイバー攻撃、医療、規制、投資など）は元資料だけでなく独立した補足資料を必要とし、得られない場合は**保留**する。一次情報が広告文言や架空ベンチマークなら同じく保留。
- ニュース重複はURL/見出し一致だけでなく、発表の意味内容・既報との差分・不採用履歴を確認する。近い発表の後追いは新情報が明確なときだけ。
- **現行の`approvedBy: site-owner`をモデルが自称して埋めることは禁止。** 将来の新しい自動公開レーンには`approvedBy: autonomous-editorial-policy`などの真実の認可由来と、事前にオーナーが承認したポリシー改訂SHA・全監査証跡・原稿SHA・画像SHA・検証実行IDを添えて区別する。既存人手承認レーンはそのまま維持する。
- 監査で設定したしきい値を満たした場合のみ独立PRを介して即時公開。品質CI・静的サイトBuild・本番デプロイと記事/画像/CTAのHTTP確認まで測り、失敗時は再実行・安全停止できるようにする。
- **自動公開をONにする合格基準は未成立。** 過去の実際の合格記事と、不採用・差分不明・日付矛盾・注入攻撃・404・容量超過のケースを使用して精度/誤掲載率/重複率を検証する。モデル自身の数値評価だけで合格を決めない。事前の編集憲章に基づく公開許可であって、毎回人間の個別承認を要求する制度には戻さない。

## 原則

「ニュースは価値があれば何本でも即時公開」「根拠がなければ1本も公開しない」。GitHubの公開処理は既存の即時公開レーンを活用するが、毎時RSS取得の成功を編集承認とみなさない。失敗ログには現象、直接原因、構造的原因、修正、回帰テストと本番確認の結果を記録する。
